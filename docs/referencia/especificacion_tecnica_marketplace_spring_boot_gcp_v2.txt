================================================================================
ESPECIFICACIÓN TÉCNICA Y ARQUITECTURA DEL SISTEMA MARKETPLACE MULTI-ROL 
(SPRING BOOT + GCP) - V2
================================================================================

Este documento consolida la arquitectura, tecnologías, estándares de diseño, 
seguridad OWASP y la definición del catálogo de servicios HTTP segmentado 
según el control de acceso basado en roles (RBAC): Administrador, Vendedor 
(Seller), Comprador (Buyer) y Público/Invitado.


================================================================================
1. STACK TECNOLÓGICO RECOMENDADO
================================================================================

1.1 Backend Services (API REST)
-------------------------------
• Spring Boot 3 + Java 21: Microservicios con Spring MVC / WebFlux, Spring Data 
  JPA y Spring Security.
• Spring Security (JWT + RBAC): Gestión de roles mediante anotaciones 
  @PreAuthorize("hasRole('ADMIN')"), @PreAuthorize("hasRole('SELLER')") o 
  @PreAuthorize("hasRole('BUYER')").
• Gradle / Maven: Gestor de dependencias y automatización de builds.

1.2 Frontend & Cliente Web
--------------------------
• Next.js (React) / Angular: Implementación de SSR/ISR para optimizar SEO y 
  rendering diferenciado por paneles de usuario (Portal del Comprador, 
  Dashboard del Vendedor, Panel de Control del Administrador).
• Tailwind CSS + Shadcn UI: Interfaz moderna, limpia, responsiva y optimizada 
  para la conversión.

1.3 Persistencia, Caché e Infraestructura (GCP)
-----------------------------------------------
• Cloud SQL (PostgreSQL): Base de datos relacional administrada para 
  transacciones y control de inventarios multitienda.
• Memorystore for Redis (GCP): Almacenamiento en caché para catálogos, 
  sesiones y reducción de carga en base de datos.
• Cloud Run: Despliegue de los servicios REST de Spring Boot en contenedores 
  Docker con autoescalado.
• Cloud Load Balancing & Cloud CDN: Balanceador de carga HTTPS y distribución 
  global de contenido.
• Cloud Storage (GCS): Almacenamiento persistente de imágenes de productos de 
  cada vendedor.
• Secret Manager: Gestión segura de credenciales de base de datos, llaves API 
  y tokens.
• Cloud Logging & Monitoring: Trazabilidad de logs y monitoreo de recursos 
  en tiempo real.

3. MEJORES TÉCNICAS DE DESARROLLO WEB CON SPRING BOOT
================================================================================

• Arquitectura Hexagonal (Puertos y Adaptadores): Desacoplamiento de la lógica 
  de negocio respecto al framework y controladores REST.
• Manejo Global de Excepciones: Implementación de @ControllerAdvice con el 
  formato estandarizado RFC 7807 (Problem Details).
• DTOs e Inmutabilidad: Uso de Java record y MapStruct para el filtrado estricto 
  de campos según el rol de la consulta.
• Concurrencia e Inventarios Multi-Vendedor: Control de bloqueos JPA (Pessimistic 
  Locking) al reservar productos en Cloud SQL.
• Patrón de Resiliencia: Integración de Resilience4j para tolerar fallos en el 
  cálculo de envíos o consumo de pasarelas.


================================================================================
4. SEGURIDAD Y REGLAS OWASP PARA SERVICIOS WEB
================================================================================

• Autenticación y RBAC (OWASP API1 & API2): Control de acceso fino mediante 
  Spring Security y tokens JWT con claims de rol explícitos.
• Validación de Entradas (OWASP API8): Inyección de spring-boot-starter-validation 
  en DTOs para evitar SQLi y XSS.
• Protección de Datos (OWASP API3): Comunicaciones seguras vía HTTPS/TLS 1.3 y 
  secretos almacenados en GCP Secret Manager.
• Limitación de Tasa por Rol (OWASP API4): Rate limiting configurado en Cloud 
  Armor o Bucket4j (umbrales más altos para administradores/vendedores que 
  usuarios anónimos).
• Cabeceras de Seguridad: Aplicación de reglas CSP, X-Frame-Options, 
  X-Content-Type-Options y HSTS.


================================================================================
5. ESTÁNDARES DE DISEÑO API RESTFUL
================================================================================

• URIs Segmentadas por Recurso y Contexto: Prefijos claros (/api/v1/buyer/..., 
  /api/v1/seller/..., /api/v1/admin/...).
• Verbos HTTP Semánticos: Empleo de GET, POST, PUT, PATCH y DELETE según la 
  operación.
• Paginación y Filtrado: Soporte para consultas masivas con Pageable de Spring 
  Data en catálogos y listados de órdenes.
